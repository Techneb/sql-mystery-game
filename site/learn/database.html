The bakery database

Every example in this handbook runs on this one small, invented database, so you only have to learn its tables once.

The bakery sells twenty products and keeps six tables. They record four weeks of trade, from Monday 2 March to Sunday 29 March 2026; the shop is closed on Fridays.

TableColumnsOne row is
customerid, name, town, joined, referred_by, emaila regular customer; referred_by is the id of the customer who recommended the shop, or NULL; email is as the customer wrote it (some in capitals or with a stray space), or NULL
productid, name, category, pricesomething on sale: bread, pastry or cake, today's price in euros
staffid, name, role, manager_idsomeone who works at the bakery; manager_id is the id of their manager, NULL for the owner
ordersid, customer_id, day, time, staff_idone visit to the counter; day is YYYY-MM-DD, time is HH:MM, staff_id who served it
order_itemorder_id, product_id, quantity, unit_priceone line of an order: how many of one product, at the price paid that day (three products cost more from Monday 16 March)
refundid, order_id, day, amount, reasonmoney given back on an order, in euros; reason may be NULL

The ids link the tables: each order line points to its order and its product, each order to its customer and to the member of staff who served it, each refund to its order, a customer to the customer who referred them, and a member of staff to their manager. The schema draws those links: a gold key marks each primary key, a silver one each foreign key, and every line runs from a foreign key (N, many rows can share a value) to the key it points to (1). The loop beside customer is referred_by, and the one beside staff is manager_id: each points back into its own table.

primary key foreign key one-to-many

The full database is forty customers, twenty products, six staff, 303 orders, 680 order lines and eight refunds. To run the examples yourself, paste this script into any SQLite tool (the sqlite3 command line, DB Browser for SQLite, or an online SQLite playground), then try each query from the pages below. The examples follow the rules of this site's terminal, and plain SQLite differs from it in one place that matters for them: there LIKE ignores case and ILIKE does not exist, so write lower(name) LIKE '%croissant%' instead of ILIKE.

The bakery database as a SQLite script 
CREATE TABLE customer (id INTEGER PRIMARY KEY, name TEXT, town TEXT, joined TEXT, referred_by INTEGER REFERENCES customer(id), email TEXT);
CREATE TABLE product (id INTEGER PRIMARY KEY, name TEXT, category TEXT, price REAL);
CREATE TABLE staff (id INTEGER PRIMARY KEY, name TEXT, role TEXT, manager_id INTEGER REFERENCES staff(id));
CREATE TABLE orders (id INTEGER PRIMARY KEY, customer_id INTEGER REFERENCES customer(id), day TEXT, time TEXT, staff_id INTEGER REFERENCES staff(id));
CREATE TABLE order_item (order_id INTEGER REFERENCES orders(id), product_id INTEGER REFERENCES product(id), quantity INTEGER, unit_price REAL);
CREATE TABLE refund (id INTEGER PRIMARY KEY, order_id INTEGER REFERENCES orders(id), day TEXT, amount REAL, reason TEXT);
