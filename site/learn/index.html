The clerk's handbook

Short, plain-English pages on the SQL that The Ritz Affair asks of its players, from a first SELECT to a recursive query.

What these pages are

The Ritz Affair is a detective game played by writing SQL in the browser. Each of its twelve chapters practises one construct. This handbook is the reference a player keeps open in another tab: one page per construct, written for a student in a first SQL course, with examples whose results you can check.

The pages do not discuss the game's case. Every example runs on a separate, deliberately ordinary database: a small neighbourhood bakery. Nothing here gives away a chapter, and nothing here needs the game to make sense. You can read the handbook on its own, as a short introduction to SQL.

All the examples are SQLite, the database engine the game runs in your browser. Almost everything carries over to PostgreSQL, MySQL and other databases; the few places where SQLite behaves differently are pointed out.

The example database: a bakery

The bakery sells ten products and keeps four tables. They record one week of trade, from Monday 2 March to Sunday 8 March 2026.

The full database is eight customers, ten products, fourteen orders and twenty-three order lines. To run the examples yourself, paste this script into any SQLite tool (the sqlite3 command line, DB Browser for SQLite, or an online SQLite playground), then try each query from the pages below.

The bakery database as a SQLite script 
CREATE TABLE customer (id INTEGER PRIMARY KEY, name TEXT, town TEXT, joined TEXT, referred_by INTEGER REFERENCES customer(id));
CREATE TABLE product (id INTEGER PRIMARY KEY, name TEXT, category TEXT, price REAL);
CREATE TABLE orders (id INTEGER PRIMARY KEY, customer_id INTEGER REFERENCES customer(id), day TEXT, time TEXT);
CREATE TABLE order_item (order_id INTEGER REFERENCES orders(id), product_id INTEGER REFERENCES product(id), quantity INTEGER);

The pages

  1. Tables, keys and the schema: what a primary key and a foreign key are, and how to explore a database you have never seen.
  2. SELECT and WHERE: choosing columns, filtering rows, AND, OR, IN, BETWEEN and IS NULL.
  3. ORDER BY and LIMIT: sorting on one or several keys, keeping the top rows, and the trap of ties.
  4. LIKE and text patterns: the percent and underscore wildcards, and case in SQLite.
  5. GROUP BY, aggregates and HAVING: counting and summing per group, and filtering groups.
  6. JOIN, LEFT JOIN and self-joins: combining tables, finding what is missing, and joining a table to itself.
  7. CASE WHEN: labels, buckets, conditional counts and custom sort orders.
  8. Window functions: RANK and LAG: ranking within groups and comparing a row with the previous one.
  9. CTEs and WITH RECURSIVE: building a query in named steps, following chains and generating dates.

And two pages about the game itself: How to play explains the screen and the two modes, and For teachers explains how to run a class session.
