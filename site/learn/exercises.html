SQL exercises with solutions

Game: practice for every chapter

Reading about SQL is not the same as writing it. Fifteen questions on the bakery database, from a first filter to a recursive chain, each with a worked solution kept out of sight until you want it.

How to use this page

The terminal on this page runs your queries on the bakery database, by the same rules as the game's: choose a question, write your query, press Run, and the page says whether your result answers it (same rows, whatever the column names; in the order asked when the question asks for one). The buttons above the question list choose a level. It remembers, in this browser only, the questions you have solved and the queries you ran (the History under the terminal; click one to put it back in the box). You can also create the database with the script on the bakery database page (any SQLite tool will do; every solution below also passes this site's terminal. In plain SQLite, write lower(name) LIKE '%croissant%' instead of ILIKE). Read a question, write your query, run it, and only then open the solution to compare. Many questions have several correct answers; if your result has the same rows, your query is right, even if it reads differently. Every solution ends with an ORDER BY that fixes the order of its rows, so that yours can be compared line by line.

The exercises come in three grades. Warm-up uses one table at a time. Practice joins tables, groups rows and builds a first two-step query or stacks two results. Challenge needs more careful reasoning: the absence of a row, window functions or a recursive CTE. Each one names the handbook page that covers what it needs. Each also says how many rows a correct answer returns.

    Warm-up
    

    1. The cheap shelf. List the name and price of every product that costs less than 2, cheapest first. (SELECT and WHERE, ORDER BY) · Expected: 3 rows.
    

    Solution

    SELECT name, price
FROM product
WHERE price < 2
ORDER BY price, id;
    

    

    nameprice
    

    Baguette1.2
    

    Croissant1.4
    

    Pain au chocolat1.6
    

    

    The id after price breaks ties. There are none here, but a second key costs nothing and keeps the order fixed if a new product ever shares a price.
    

    


    2. Early customers. Which customers joined before June 2024, and from which town? Show the most recent first. (Dates and times) · Expected: 6 rows.
    

    Solution

    SELECT name, town, joined
FROM customer
WHERE joined < '2024-06-01'
ORDER BY joined DESC;
    

    

    nametownjoined
    

    Farid HaddadOld Town2024-05-19
    

    Emma NovakHillcrest2024-04-02

    "Before June" means before the first of June, so the comparison is a strict < against '2024-06-01', written in the column's own ISO shape. joined <= '2024-05-31' gives the same rows here.
    

    


    3. Every croissant. Find the products whose name contains the letters croissant anywhere, on their own or inside a longer word, whatever their case. (LIKE) · Expected: 2 rows.
    

    Solution

    SELECT id, name
FROM product
WHERE name ILIKE '%croissant%'
ORDER BY id;
    

    

    idname
    

    4Croissant
    

    6Almond croissant
    

    

    LIKE '%croissant%' would miss the plain Croissant, whose capital C does not match a small c: LIKE is case-sensitive (see LIKE and ILIKE). The wildcard at the front is what finds the almond one.
    

    


    4. The counter by category. For each category, show how many products it has and the price of the dearest one. (GROUP BY) · Expected: 3 rows.
    

    Solution

    SELECT category, COUNT(*) AS products, MAX(price) AS dearest
FROM product
GROUP BY category
ORDER BY category;
    

    

    categoryproductsdearest
    

    bread44.5
    

    cake33.9
    

    pastry32.2
    

    

    Asking for the name of the dearest product is a different and harder question: name is neither grouped nor aggregated, so it cannot simply be added to this SELECT. Exercise 13 shows the pattern, with a window function.
    

    


    Practice
    

    5. Orders by town. How many orders did the customers of each town place? List only the towns with at least one order, busiest town first. (JOIN, GROUP BY) · Expected: 3 rows.
    

    Solution

    SELECT c.town, COUNT(*) AS orders
FROM orders AS o
JOIN customer AS c ON c.id = o.customer_id
GROUP BY c.town
ORDER BY orders DESC, c.town;
    

    

    townorders
    

    Riverside7
    

    Hillcrest4
    

    Old Town3
    

    

    The town lives in customer and the orders in orders, so the join comes first and the grouping after it. Each row of the join is one order, which is why COUNT(*) counts orders.
    

    


    6. Takings per day. How much money did the bakery take on each day it had orders (days without an order are left out)? Round each day's total to two decimal places. (JOIN, GROUP BY) · Expected: 6 rows.
    

    Solution

    SELECT o.day, ROUND(SUM(oi.quantity * p.price), 2) AS takings
FROM orders AS o
JOIN order_item AS oi ON oi.order_id = o.id
JOIN product AS p ON p.id = oi.product_id
GROUP BY o.day
ORDER BY o.day;
    

    

    daytakings
    

    2026-03-0221.0
    

    2026-03-034.2
    

    2026-03-049.5
    

    2026-03-0512.1
    

    2026-03-0719.1
    

    2026-03-0818.8
    

    

    The money of a line is its quantity times the product's price, so three tables take part. The sixth of March is missing because nobody ordered that day: a group needs rows. The CTE page builds a calendar that shows such a day with zero.
    

    


    7. Busy hours. Take an order's hour as the first two characters of its time ('07' for 07:20). Which hours had at least two orders over the whole week, busiest first? (Dates and times, HAVING) · Expected: 2 rows.
    

    Solution

    SELECT substr(time, 1, 2) AS hour, COUNT(*) AS orders
FROM orders
GROUP BY hour
HAVING COUNT(*) >= 2
ORDER BY orders DESC, hour;
    

    

    hourorders
    

    074
    

    082
    

    

    The hour is the first two characters of the time. Keeping it as text is fine for grouping and sorting, because every hour has two digits; a CAST would only be needed for arithmetic.
    

    


    8. Referred from afar. List the customers who were referred by someone living in a different town, with both towns. (Self-joins) · Expected: 4 rows.
    

    Solution

    SELECT newcomer.name, newcomer.town, referrer.name AS referrer, referrer.town AS referrer_town
FROM customer AS newcomer
JOIN customer AS referrer ON referrer.id = newcomer.referred_by
WHERE newcomer.town <> referrer.town
ORDER BY newcomer.id;
    

    

    nametownreferrerreferrer_town
    

    Ben OkaforHillcrestAlice TurnerRiverside
    

    Emma NovakHillcrestChloe MartinRiverside
    

    Farid HaddadOld TownEmma NovakHillcrest
    

    Grace LeeRiversideBen OkaforHillcrest
    

    

    The same table plays two parts under two aliases. The inner join leaves out the customers who were not referred at all, which is right here: they have no referrer whose town could differ.
    

    


    9. Morning people. For each customer who has ordered, show the number of orders placed before nine o'clock and the number placed at nine o'clock or later, side by side. (CASE WHEN) · Expected: 7 rows.
    

    Solution

    SELECT c.name,
       SUM(CASE WHEN o.time < '09:00' THEN 1 ELSE 0 END) AS before_nine,
       SUM(CASE WHEN o.time >= '09:00' THEN 1 ELSE 0 END) AS later
FROM customer AS c
JOIN orders AS o ON o.customer_id = c.id
GROUP BY c.id, c.name
ORDER BY before_nine DESC, c.id;
    

    

    namebefore_ninelater
    

    Alice Turner31
    

    Chloe Martin20
    

    Ben Okafor11
    

    David Chen02
    

    Emma Novak02
    

    Farid Haddad01
    

    Grace Lee01
    

    

    Each CASE turns an order into a 1 or a 0, and the SUM counts the ones. Writing the second condition as >= '09:00' rather than > '09:00' makes sure an order at exactly nine is counted once, in the later column.
    

    


    10. Above their category. Which products cost more than the average price of their own category? Show that average too. (Subqueries, CTEs) · Expected: 5 rows.
    

    Solution

    WITH category_average AS (
  SELECT category, AVG(price) AS average
  FROM product
  GROUP BY category
)
SELECT p.name, p.category, p.price, ROUND(a.average, 2) AS average
FROM product AS p
JOIN category_average AS a ON a.category = p.category
WHERE p.price > a.average
ORDER BY p.category, p.price DESC, p.id;
    

    

    namecategorypriceaverage
    

    Sourdough loafbread4.53.32
    

    Rye loafbread3.83.32
    

    Seeded rollsbread3.83.32
    

    Lemon tartcake3.93.3
    

    Almond croissantpastry2.21.73
    

    

    A correlated subquery in WHERE finds the same products, but showing the average as well would mean writing it twice. A CTE computes each category's average once and joins it like a table.
    

    


    11. Not on the weekend menu. Which products were never bought on the weekend of 7 and 8 March? Include the products nobody bought at all. Answer with a set operation. (EXCEPT) · Expected: 2 rows.
    

    Solution

    SELECT name
FROM product
EXCEPT
SELECT p.name
FROM product AS p
JOIN order_item AS oi ON oi.product_id = p.id
JOIN orders AS o ON o.id = oi.order_id
WHERE o.day >= '2026-03-07'
ORDER BY name;
    

    

    name
    

    Carrot cake slice
    

    Rye loaf
    

    

    Every product, minus the ones sold at the weekend. The first half reads product alone, so the carrot cake, which nobody bought all week, is in the answer too; a join on its own could never show it. Comparing names works because no two products share one; with a column that can repeat, compare the ids. Exercise 12 asks the same kind of question with NOT EXISTS.
    

    


    Challenge
    

    12. No bread, thank you. Which customers have never bought any bread? Include anyone who has never bought anything. (Subqueries) · Expected: 4 rows.
    

    Solution

    SELECT c.name
FROM customer AS c
WHERE NOT EXISTS (SELECT 1
                  FROM orders AS o
                  JOIN order_item AS oi ON oi.order_id = o.id
                  JOIN product AS p ON p.id = oi.product_id
                  WHERE o.customer_id = c.id
                    AND p.category = 'bread')
ORDER BY c.id;
    

    

    name
    

    Chloe Martin
    

    Emma Novak
    

    Grace Lee
    

    Hugo Silva
    

    

    The tempting answer joins everything and filters WHERE p.category <> 'bread', but that lists the customers who bought something that is not bread, which includes bread buyers who also took a croissant, and drops Hugo Silva, who bought nothing. The question is about the absence of a row, which is what NOT EXISTS asks.
    

    


    13. Best seller of each category. For each category, which of the products that sold at least once sold the most pieces over the week? Keep ties, if there are any. (Window functions) · Expected: 3 rows.
    

    Solution

    WITH sold AS (
  SELECT p.category, p.name, SUM(oi.quantity) AS pieces
  FROM product AS p
  JOIN order_item AS oi ON oi.product_id = p.id
  GROUP BY p.id, p.category, p.name
),
ranked AS (
  SELECT category, name, pieces,
         RANK() OVER (PARTITION BY category ORDER BY pieces DESC) AS rk
  FROM sold
)
SELECT category, name, pieces
FROM ranked
WHERE rk = 1
ORDER BY category, name;
    

    

    categorynamepieces
    

    breadBaguette6
    

    cakeChocolate eclair5
    

    pastryCroissant6
    

    

    Three steps: add up the pieces per product, rank the products within each category, keep the first. RANK gives tied products the same rank 1, so a tie would show both; ROW_NUMBER would keep just one, chosen arbitrarily. The filter has to sit outside the CTE, because a window function cannot appear in WHERE.
    

    


    14. Back again. Put each customer's orders in sequence by day, then time. For every order that is not a customer's first, show the order's id and the day of that customer's previous order in the sequence. (Window functions, NULL) · Expected: 7 rows.
    

    Solution

    WITH visits AS (
  SELECT id, customer_id, day,
         LAG(day) OVER (PARTITION BY customer_id ORDER BY day, time) AS previous_day
  FROM orders
)
SELECT id, customer_id, previous_day, day
FROM visits
WHERE previous_day IS NOT NULL
ORDER BY customer_id, day;
    

    

    idcustomer_idprevious_dayday
    

    512026-03-022026-03-04
    

    912026-03-042026-03-07
    

    1412026-03-072026-03-08
    

    822026-03-022026-03-05
    

    1232026-03-032026-03-08
    

    1142026-03-022026-03-07
    

    1352026-03-042026-03-08
    

    

    A customer's first order has no previous row, so LAG returns NULL for it, and IS NOT NULL drops exactly those orders. Ordering the window by day, time rather than day alone keeps two orders on the same day in their real order.
    

    


    15. Word of mouth. Customers who walked in on their own (no referrer) brought others, who brought others in turn. How many customers does each walk-in account for, directly or down the chain, not counting the walk-in themself? A walk-in who brought nobody counts 0. (WITH RECURSIVE) · Expected: 3 rows.
    

    Solution

    WITH RECURSIVE chain(root_id, id) AS (
  SELECT id, id FROM customer WHERE referred_by IS NULL
  UNION ALL
  SELECT ch.root_id, c.id
  FROM chain AS ch
  JOIN customer AS c ON c.referred_by = ch.id
)
SELECT r.name, COUNT(*) - 1 AS brought
FROM chain AS ch
JOIN customer AS r ON r.id = ch.root_id
GROUP BY r.id, r.name
ORDER BY brought DESC, r.id;
    

    

    namebrought
    

    Alice Turner5
    

    David Chen0
    

    Hugo Silva0
    

    

    The anchor starts one chain per walk-in, carrying the walk-in's id as root_id; each round adds the customers referred by the newest members and passes the same root_id down. Every chain contains its walk-in too, hence the - 1. Because the walk-ins start their own chains, a walk-in who brought nobody still appears, with 0.
